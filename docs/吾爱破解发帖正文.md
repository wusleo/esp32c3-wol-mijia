## 正文

### 一、起因

台式机放在书房，人在公司想连回去干活。试过向日葵开机棒，也试过主板自带的 WOL，问题都很具体：

- 主板 WOL 需要路由器做端口映射或者内网穿透，配置麻烦；
- 想用语音控制，得额外接智能插座再搞软路由；
- 网上现成的 WOL 固件基本都是 Arduino 写的，功耗感人——**插着 USB 一直在线，80~100mA，根本没法用电池**。

于是自己写了一个。目标很明确：**小爱一句话开机，一节 18650 撑几个月，而且装在机箱里之后还能远程升级固件**。

前两个目标不算难，第三个才是真正的坑（后面细说）。

---

### 二、成品效果

- 米家 App 点按，或对小爱说「打开电脑」，台式机从**完全关机**状态唤醒（已实测跑通）
- 板子处于 light sleep 时，从收到 MQTT 指令到发出魔术包 **1.2 秒**
- 整机跑在 light sleep 下，平均电流亚毫安级
- 需要改固件时，手机发一条 `debug` 指令给设备，串口就恢复了，直接在电脑上烧录，**不用拆机箱、不用按键**

#### 烧完不用改代码，手机网页里配

这块是我特意为「不想装 ESP-IDF 的兄弟」加的。固件烧好，第一次上电它会自己变成一个热点：

1. 手机 WiFi 列表里连 **`WOL-Setup-XXXX`**（开放热点，没密码）
2. 手机一般会自动弹出配置页，没弹就手动开 **http://192.168.4.1**
3. 填五项：WiFi 名称（可以点「扫描」从周围列表里选）、WiFi 密码、巴法云 UID、巴法云**主题值**（那串字母数字，不是昵称）、电脑有线网卡 MAC
4. 点「保存并重启」

> 主题值这一步踩过坑：巴法云会同时显示「主题值 `aB3xY9kLm006`」和「昵称 `客厅电脑`」，填成昵称设备照样能连上 MQTT，但收不到任何消息。完整的九步图解在文末附录。

设备写 flash → 关热点 → 重启 → 连上你家 WiFi。**全程不用碰编译环境，也不用装任何 App。**

底层实现没用 ESP-IDF 官方的 `wifi_provisioning`，因为它要配手机 App，国内装 App 这一步劝退率太高。这里是三样东西自己拼的：

| 组件 | 作用 |
|---|---|
| SoftAP + `esp_http_server` | 开热点、跑配置页、`/scan` 返回周边 WiFi 列表 |
| UDP 53 DNS 劫持 | 把所有域名都答成 192.168.4.1，手机就会自动弹页面（captive portal）|
| NVS | 配置存 `wolcfg` 命名空间，掉电不丢 |

配置页是独立文件 `main/index.html`，编译时用 `EMBED_FILES` 嵌进固件，改文案不用动 C 代码。

### 三、材料清单与接线

**方案 A：插电（最省事）**

一根 USB 线，不需要任何额外元件：

| 物料 | 说明 | 价格 |
|---|---|---|
| ESP32-C3 SuperMini | 4MB Flash，Type-C 直连芯片 | ¥9~15 |
| USB 充电头 | 5V 1A 以上，手机充电头即可 | ¥3~5 |
| USB-C 数据线 | 必须是**数据线**，只充电线认不到板子 | ¥2~5 |

合计 ¥14~25。缺点是要占一个插座，断电就没了。

**方案 B：18650 电池（一节跑几个月）**

| 物料 | 说明 | 数量 | 价格 |
|---|---|---|---|
| 18650 锂电池 | 必须带保护板，2000mAh 以上 | 1 | ¥8~15 |
| **HT7333 LDO** | **TO-92 直插**，3.3V 固定输出 | **3** | ¥1/颗 |
| 18650 电池盒 | 单节，带引线最好 | 1 | ¥2~3 |
| 接线端子 | 2 位螺丝端子 5.08mm 或 WAGO 221 | 3 | ¥1~2 |
| 单芯线 / 杜邦线 | 22AWG 单芯线最好插 | 若干 | ¥2 |
| 电解电容 100µF | **可选**，出现随机重启再补 | 1 | ¥0.5 |
| TP4056 充电模块 | **可选**，想机箱内充电才加（需焊 4 根线） | 1 | ¥2~5 |

合计 ¥24~38。

HT7333 买三颗不是凑数，原因下面会说。

#### 接线：4 根线，全程不用烙铁

```
电池盒 +     ──────────► HT7333 VIN
电池盒 −     ──┬───────► HT7333 GND
               └───────► ESP32-C3 GND
HT7333 VOUT  ──────────► ESP32-C3 3V3
```

1. HT7333 三根脚分别插进三个端子孔，一根脚占一个孔
2. 电池盒的 `+` 线接「VIN」端子
3. 电池盒的 `−` 线接「GND」端子，再从同一个端子引一根线到板子的 `GND`
4. 从「VOUT」端子引一根线到板子的 `3V3`
5. 上电池，量板子 `3V3` 对 `GND`，**3.2~3.4V 就成功了**

那根地线是一根串下去的：电池负极 → LDO 的 GND → 板子的 GND，不用分叉。

#### 不用学认引脚：买三颗直接试

HT7333 的 TO-92 封装有两种引脚排列，买到哪种全看厂家批次：

| 排列 | 正面（印字朝自己、引脚朝下）从左到右 |
|---|---|
| TO-92-A | **GND** · **VIN** · **VOUT** |
| TO-92-B | **VIN** · **GND** · **VOUT** |

中间那根可能是 GND，也可能是 VIN。不用研究手里是哪一种，先按 TO-92-A 接上，量输出：

| 量到的电压 | 说明 | 怎么办 |
|---|---|---|
| 3.2~3.4V | 接对了 | 收工 |
| ≈ 4.2V（等于电池电压） | VIN / VOUT 反了 | 断电，这两根对调 |
| 0V | 中间那根不是 GND | 换一颗，按 TO-92-B 接 |

一块钱一颗，烧掉一颗的成本远低于对着万用表研究半小时。

#### 电容为什么可以省

网上教程都说输出必须并 100µF，我实际算了一遍，**这个项目可以不接**：

- 18650 内阻只有 50~100mΩ，240mA 发射峰值在电池上只掉 15~25mV，LDO 输入基本不塌
- HT7333 输出能力 250mA，正好覆盖这个峰值
- SuperMini 板载 3V3 网络上本来就有 10µF + 100nF 陶瓷电容

只有三种情况需要补：电池老化内阻变大、端子虚接、线太长太细。症状很好认——**随机重启、日志莫名从启动重新开始**。真遇到了，在 VOUT 与 GND 之间补一颗 100µF 电解即可，不用重新布线。

> ⚠️ 电解电容有极性，外壳印着白边的那侧是负极，接反会鼓包。

#### 这里有个关键选择：LDO 还是升压模块

网上大部分教程（包括我最初看的那份）都让你用 MT3608 把 3.7V 升到 5V 再喂给板子。**在超低功耗场景这是错的**：

| 方案 | 转换效率 | 模块自身静态电流 |
|---|---|---|
| MT3608 升到 5V → 板载 LDO 再降到 3.3V | 约 46%（0.7 × 0.66） | **1~2 mA** |
| LDO 直接 3.7V → 3.3V，绕过板载 LDO | 约 89% | 2.5 µA（HT7333） |

目标负载只有 0.3mA 量级，而 MT3608 空载就要吃 1~2mA —— **它自己比整机还耗电**，直接把续航砍掉一个数量级。

所以选 LDO，并且只认一个硬指标：**静态电流必须是 µA 级**。

- ✅ HT7333（250mA / 2.5µA typ / 4µA max，有 TO-92 直插）、ME6211C33（500mA / 40µA）、MCP1700（250mA / 1.6µA）
- ❌ AMS1117（静态 5mA）—— 绝对不能用，它自己就比整机耗电十几倍

**三条必须遵守的接线纪律：**

1. **接的是 `3V3` 脚，不是 `5V` 脚。** 接 5V 就会走进板载那颗稳压芯片，省电努力全白费。
2. **绝不能同时插 USB。** 板载 LDO 输出和 USB 供电路径挂在同一个 3V3 网络上，两边同时供电会互相倒灌，轻则重启重则烧芯片。
3. **端子拧完拉一下线。** 虚接会让板子在发射瞬间掉电重启，现象是「随机重启、日志无故从启动开始」，很难联想到是接触不良。

### 电脑侧必做的三件事（不做就唤不醒）

硬件做完了，但**电脑那边默认是收不到魔术包的**。我第一次测试失败就是漏了这些：

**1. BIOS 里关掉 ErP / EuP**

这是最关键的一项。`ErP Ready` 是欧盟的待机功耗标准，开启后关机时会**把网卡的待机供电整个切断**，这时候发什么魔术包都没人接。

进 BIOS（多数主板是开机连按 `Del`，进去后按 `F7` 切到高级模式），路径一般在 `Advanced → Power Management Setup`：

| 选项 | 设为 |
|---|---|
| `ErP` / `ErP Ready` / `EuP` | **Disabled** ← 最关键 |
| `Wake on LAN` / `Power On By PCI-E` | Enabled |
| `Deep Sleep` / `Deep S5` | Disabled |

**2. Windows 关掉「快速启动」**

快速启动本质是休眠，关机时网卡被置于 D3 状态，很多主板在这个状态下的 WOL 是失效的。

以管理员身份跑：

```powershell
powercfg /h off
```

或者改注册表 `HKLM\SYSTEM\CurrentControlSet\Control\Session Manager\Power` 下的 `HiberbootEnabled` 为 `0`。

**3. 网卡属性里允许魔术包唤醒**

设备管理器 → 网络适配器 → 你的有线网卡 → 属性 → 高级：

| 项 | 设为 |
|---|---|
| `Wake on Magic Packet` | Enabled |
| `Shutdown Wake-On-Lan` | Enabled |

再到「电源管理」页，勾上「允许此设备唤醒计算机」。

验证命令（有输出且包含你的网卡就对了）：

```powershell
powercfg /devicequery wake_armed
```

> 注意：**必须是网线口的 MAC**。WiFi 网卡在关机后是完全断电的，收不到魔术包。

### 四、为什么不能用 Arduino 方案

这是我想重点说的一件事，很多人踩过这个坑还在原地打转。

你在 Arduino 里写：

```cpp
esp_pm_configure(&cfg);
```

它永远返回 `ESP_ERR_NOT_SUPPORTED`。

原因不在你的代码，在 Arduino-ESP32 的预编译二进制库——它编译时的 `sdkconfig` 里 `CONFIG_PM_ENABLE` 根本没打开。电源管理框架整个没被编进去，light sleep 无从谈起。

你能用的只有 `WiFi.setSleep(true)`（modem sleep），实测电流卡在 **11mA**，2000mAh 的电池大约撑 7 天。

换成 ESP-IDF 自己编译之后：

```
I (6403) pm: Frequency switching config: CPU_MAX: 160, APB_MAX: 80, APB_MIN: 40, Light sleep: ENABLED
I (6403) LS: [OK] esp_pm_configure = ESP_OK, light sleep enabled
```

平均电流才能压到亚毫安。**这是必须换 ESP-IDF 的唯一原因，也是这个项目真正的技术含量所在。**

### 五、真正的难点：省电和维护是死对头

这是整个项目里最花时间的一段，也是我觉得最值得分享的部分。

#### 问题

ESP32-C3 的串口走的是**原生 USB-Serial/JTAG**（不用 CH340）。而它在 light sleep 状态下会把 USB PHY 的时钟关掉。

后果是：**芯片一睡，串口立刻消失**。电脑上设备管理器直接认为设备被拔出了，既看不到日志，也烧不了固件。

我第一次烧进去带 light sleep 的固件，板子跑了十分钟就再也连不上了。当时以为是固件跑飞了，后来才发现人家活得好好的——巴法云后台一直显示在线，只是串口这条线断了。

#### 试过但没用的事

- **发 MQTT 把它叫醒？** 会醒，但 WiFi beacon 给的唤醒窗口是微秒级，USB 枚举需要毫秒级连续通信，接不上。
- **让 CPU 一直醒着？** 光是 CPU 醒着不够。C3 在睡眠时会撤掉 USB 的 D+ 上拉，主机早就认定设备没了；醒来时 ESP-IDF 也不会自动重建 PHY，得固件显式重装驱动。而那个"显式的动作"，人在板子外面根本触发不了。
- **设备管理器里禁用再启用（软件拔插）？** 这是我踩得最惨的一个坑。对睡着的芯片做这个操作，会把它从 Windows 设备树里摘掉。芯片在睡无法重新枚举，之后 `GetPortNames()` 直接返回空，`pnputil /scan-devices` 反复扫十几次都找不回来。**只能物理重插。**

#### 解法：留一条电源锁后门

思路其实很简单——**别让它睡**。

固件里预创建一把 `ESP_PM_NO_LIGHT_SLEEP` 锁：

```c
esp_pm_lock_create(ESP_PM_NO_LIGHT_SLEEP, 0, "remote_debug", &s_lock);
```

MQTT 收到 `debug` 指令时拿住这把锁，CPU 就不再进 light sleep，USB 时钟恢复，串口重新枚举出来：

```c
static void on_mqtt_cmd(const char *data, int len)
{
    if (payload_is(data, len, "debug")) {
        power_awake_begin(CONFIG_APP_AWAKE_WINDOW_S);   // 默认 600 秒
        bemfa_publish("debug:awake");
    }
}
```

于是远程烧录流程变成：

1. 手机发一条 `debug` 到巴法云主题
2. 等两秒，串口出现
3. `idf.py -p COMx flash`

**从此改一块装在机箱里的板子，不用拆机箱，不用按键。**

窗口到期会自动归还锁，就算忘了发 `sleep` 也不会一直耗电。

### 六、踩坑记录（都是真金白银的时间）

**1. 事件回调里不能做阻塞操作**

早期版本在 `WIFI_EVENT_STA_START` 回调里做阻塞扫描，还把 `wifi_ap_record_t ap[16]`（约 1.8KB）放在了栈上：

```
Guru Meditation Error: Core 0 panic'ed (Stack protection fault).
Detected in task "sys_evt"
Stack bounds: 0x3fca4404 - 0x3fca4f00    ← 只有 2812 字节
```

`sys_evt` 任务栈只有约 2.3KB，直接溢出。正确做法：回调里只置标志、发通知，扫描交给专用任务，数组放静态区。

**2. 睡眠之后绝对不能写日志**

USB-Serial/JTAG 在没有主机的时候，写入会**阻塞在驱动里**，等一个永远不会来的主机。

如果恰好负责「归还电源锁」的任务卡在一条日志上，那把锁就永远不还——比不睡还费电。这个 bug 特别隐蔽，因为表现是"设备一直在线、功能正常，就是电池掉得比预期快"。

我的做法是开启 light sleep 成功后直接 `esp_log_level_set("*", ESP_LOG_NONE)`，整机静音。想看日志就按住 BOOT 上电。

**3. 有些 C3 SuperMini 高功率下连不上 WiFi**

现象：密码确认没错，但日志里反复 `reason=2 (AUTH_EXPIRE)`，AP 完全不回应认证请求。

我把 SSID 密码、BSSID 锁定、底层 `esp_wifi` 参数、MAC 地址全试了一遍，甚至换了手机热点，全失败。最后用功率扫描才定位到——**这块板子的射频前端在高于 14dBm 时失真**，帧发得出去，对端解调不出来。

降到 56（单位 0.25dBm，即 14dBm）立刻连上。

如果你遇到"密码肯定对但就是连不上"，先调低功率再排查别的。

**4. 断线重连别死记 BSSID**

早期版本断线后直接用"记住的 BSSID + 信道"重连。AP 一旦切信道，或者 Mesh 把你踢到另一个节点，就陷入永久失败。

正确做法是每次重连都重新扫描，挑同 SSID 里信号最强的那个。

**5. 巴法云的 MQTT 鉴权有个坑**

`client_id`、`username`、`password` 三者**都必须是 UID**，换别的值服务器直接回 `CONNACK rc=5`。这也意味着你没法在电脑上另开一个 client 旁听同一个主题，会被拒绝。

**6. `inet_addr()` 把广播地址判成非法，我一个人查了大半天**

现象：米家里点「打开电脑」，板子毫无反应，巴法云控制台还显示设备离线。我先怀疑没连上 WiFi，又怀疑 light sleep 把 MQTT 睡断了——两轮全错。

真凶在串口日志里（30 秒宽限期内才看得到）：

```
I (24330) main: cmd "on"
E (24340) wol: bad destination: 255.255.255.255
```

指令早就到了，是固件自己把目标地址拒了。`inet_addr()` 这个函数用 `0xFFFFFFFF` 表示「解析失败」，而 `255.255.255.255` 转成二进制正好也是 `0xFFFFFFFF`——**合法广播地址和错误码撞成了同一个值**，校验永远过不去。

```c
// 错的
if (inet_addr(ip) == INADDR_NONE) { /* 255.255.255.255 永远进这里 */ }

// 对的
struct in_addr a;
if (inet_aton(ip, &a) == 0) { /* 真的解析失败 */ }
```

换成 `inet_aton()` 立刻好了。顺手把默认目标从写死的 `255.255.255.255` 改成 `auto`：连上 WiFi 后按 `IP & 掩码 | ~掩码` 算子网定向广播（`192.168.1.43/24` → `192.168.1.255`），比全局广播更容易被路由器转发，用户也不用自己算。

教训：**「设备没反应」和「设备没收到」是两件事**。日志里先确认有没有 `cmd "on"`，再看有没有 `magic packet sent`，能省掉一整晚。

**7. 巴法云的「主题值」和「昵称」是两个东西**

设备列表里每个主题显示两行：`aB3xY9kLm006` 这种字母数字串是**主题值**，「客厅电脑」这种是你自己起的**昵称**。

配置页早期写的是「主题名」，我填了昵称。设备连巴法云完全正常（日志里 `bemfa: connected` 看着没毛病），但订阅的是一个不存在的主题，米家发的消息永远到不了，控制台一直显示「订阅者：离线」——特别像设备掉线。

现在配置页改成「主题值」，加了正误对照，提交时检测到中文直接拦下。判断方法就一句：**主题值里不会有中文**。

### 七、功耗：一个被大多数人忽略的参数

先给数据：

| 模式 | 平均电流 | 2000mAh 续航 |
|---|---|---|
| 常开 | 80~100mA | 约 1 天 |
| 仅 modem sleep | 约 11mA | 约 7 天 |
| light sleep + 醒来间隔 3 beacon | 约 0.62mA | 约 37 天 |
| light sleep + 醒来间隔 10 beacon | 约 0.31mA | 约 68 天 |
| 上面再加拆掉板载 LED | 约 0.15mA | 约 110 天 |

看出来了吧，**代码层面所有优化加起来，都不如「让它少醒几次」这一件事有效。**

WiFi 设备的平均电流几乎完全由「多久醒一次听 AP 广播」决定：

```
唤醒周期 = beacon interval（AP 决定，通常 102.4ms） × 醒来间隔（设备决定）
```

#### 路子一：改路由器的 DTIM（大多数人推荐，但你很可能改不了）

DTIM 是 AP 侧的广播分发周期，改大的话所有设备都能少醒几次。听起来很美好——**但我这台运营商送的路由器，后台根本没有这一项。**

我甚至试着逆向它的 CGI 接口想直接提交参数，`/cgi-bin/luci`、`/login.cgi`、`/getpage.gch` 全 404，只回一个 `ajax_response_xml_root/IF_ERRORSTR=SessionTimeout`。放弃。

如果你也用运营商送的路由器，八成会遇到同样的情况。

#### 路子二：改固件里的 listen interval（我自己走的路，强烈推荐）

ESP-IDF 的 `wifi_sta_config_t` 里有个字段叫 `listen_interval`，语义和 DTIM 等效，但是**由设备侧发起、只影响这一台设备**：

```c
wifi_config_t wc = { 0 };
strlcpy((char *)wc.sta.ssid, SSID, sizeof(wc.sta.ssid));
strlcpy((char *)wc.sta.password, PASS, sizeof(wc.sta.password));
wc.sta.listen_interval = 10;      // 每 10 个 beacon 醒一次
esp_wifi_set_config(WIFI_IF_STA, &wc);
```

这个参数**只在 `WIFI_PS_MAX_MODEM` 模式下生效**，默认值是 3，很多人从来没动过它。

**实测对照**（我的 AP 是 `beacon interval = 102.4ms`、`DTIM = 1` 的恶劣配置）：

| listen interval | 理论唤醒周期 | 实测指令响应 |
|---|---|---|
| 3（ESP-IDF 默认） | 0.31 s | 约 6 s |
| **10（我用这个）** | **1.02 s** | **1.2 s** |

10 比 3 的唤醒次数降到 1/3.3，而响应还在 1 秒级——**这是最舒服的位置**：省电收益拿到了，语音控制的体感几乎没变。

调到 20 以上（约 2 秒醒一次）还能再省一点，但小爱下指令会出现明显等待感，不建议。

#### 最后一刀：板载 LED

C3 SuperMini 那颗红色电源灯常亮 **1.5mA**，是 light sleep 本身（0.3mA）的 5 倍。

**换句话说：不拆 LED，上面所有优化在万用表上都看不出来。** 想看到数字真正降下来，得把它旁边的限流电阻拆了。

### 十、已知限制

- 只支持 2.4GHz（C3 硬件限制）
- **WOL 只能开机，不能关机**——这是协议本身的限制，不是没做完
- 没有 OTA，升级靠 USB
- 巴法云是明文 MQTT，无 TLS
- 配网热点是**开放网络**，配置期间周围设备理论上能连上；配完立刻关掉
- **换 WiFi 密码得重新 `erase-flash` 再配**——没做「连不上就自动回配网」，这是下一步想补的

最后一条是我下一个版本要补的：连不上 WiFi 就跑回配网模式，不然改了路由器密码就得拆机箱接线刷固件，体验割裂。

### 十一、附录：保姆级配置步骤

写给完全没碰过 ESP32 的朋友。每一步都标了「怎么算成功」，卡住时按这个判断，不用猜。

#### 第 1 步 · 上电，看它自己开热点

烧录完成后设备自动重启。配置不完整的话它会进入配网模式，串口打印：

```
W (1234) provisioning:  config incomplete -> provisioning mode
W (1234) provisioning:  hotspot : WOL-Setup-E4F5  (open, no password)
W (1234) provisioning:  open    : http://192.168.4.1
```

热点名 = `WOL-Setup-` + 芯片 MAC 后两字节。MAC 是 `a0:b1:c2:d3:e4:f5`，热点就是 `WOL-Setup-E4F5`。

**✅ 成功标志**：手机 WiFi 列表里出现 `WOL-Setup-` 开头的开放热点（无锁图标）。

#### 第 2 步 · 手机连上热点，并且关掉移动数据

这一步能劝退一半人。安卓和 iOS 连上一个「不能上网」的 WiFi 时会自动切回移动数据，浏览器就再也打不开 `192.168.4.1`，表现是「页面一直转圈」或者「无法访问此网站」。

- 连上 `WOL-Setup-XXXX`
- **手动关掉移动数据**（下拉快捷面板）
- iOS 提示「无互联网连接」时选「仍要连接」

**✅ 成功标志**：WiFi 显示已连接，旁边可能带个感叹号，正常。

#### 第 3 步 · 打开配置页

浏览器地址栏手动输入，必须带 `http://`：

```
http://192.168.4.1
```

多数手机会自动弹出（captive portal 生效）；没弹就手输。别让浏览器把它升级成 https。

**✅ 成功标志**：看到「远程唤醒器 · 配网」，下面三张卡片（家里的 WiFi / 巴法云 / 要唤醒的电脑）。

#### 第 4 步 · 填 WiFi

| 字段 | 怎么填 | 注意 |
|---|---|---|
| WiFi 名称 | 点「扫描」从列表选，或手输 | **只能 2.4G**，双频合一的路由器扫到 5G 会连不上 |
| WiFi 密码 | 如实填 | 开放网络留空 |

**✅ 成功标志**：点扫描后能列出你家的 WiFi 名字，信号强度有数字。

#### 第 5 步 · 填巴法云（全流程最容易错的一步）

先登录 `cloud.bemfa.com`，取两样东西。

**UID**：个人中心里的 32 位十六进制串，形如 `0123456789abcdef0123456789abcdef`。它同时是 MQTT 的用户名和密码。

**主题值**：设备云列表里，主题卡片上那行字母数字，形如 `aB3xY9kLm006`。

⚠️ 这里有个陷阱，我自己就栽过。卡片上会同时显示两个东西：

```
主题值   aB3xY9kLm006     ← 填这个
昵称     客厅电脑          ← 别填这个
```

填成昵称，设备照样能连上巴法云（日志 `bemfa: connected` 一切正常），但它订阅的是一个不存在的主题，米家发的消息永远到不了，控制台一直显示「订阅者：离线」。

判断方法一句话：**主题值里不会有中文**。配置页现在提交时会检查，带中文直接弹窗拦下。

**✅ 成功标志**：输入框里的值是纯字母数字。

#### 第 6 步 · 填电脑的有线网卡 MAC

Windows 上开 PowerShell：

```powershell
ipconfig /all
```

找「以太网适配器 以太网」那一段（**不是** WLAN），复制「物理地址」，形如 `AA-BB-CC-DD-EE-FF`。填的时候横线或冒号都行。

填 WiFi 网卡的 MAC 没有意义——关机后无线网卡完全断电，收不到魔术包。

**✅ 成功标志**：能对上 `ipconfig /all` 里那行物理地址。

#### 第 7 步 · 保存

点「保存并重启」。之后依次：写 NVS → 关热点 → 重启 → 连你家 WiFi → 连巴法云，约 10~15 秒。

**✅ 成功标志**：页面显示「配置已保存」，几秒后手机提示热点已断开。

#### 第 8 步 · 验证（三个检查点，从板子往云端走）

**① 串口**（最可靠，前提是开机 30 秒内看）

```
I (6280) wifi: got ip 192.168.1.43
I (6400) bemfa: connected, subscribe "aB3xY9kLm006"
I (6400) main: magic dest  : auto:9
I (6400) main: grace period 30000 ms ...
```

| 看到 | 说明 |
|---|---|
| `got ip 192.168.x.x` | WiFi 通了 |
| `bemfa: connected` | MQTT 通了 |
| `subscribe "xxx"` | **这里必须和你填的主题值一字不差** |
| `grace period 30000 ms` | 30 秒调试窗口，之后进 light sleep、串口静音 |

**② 巴法云控制台**：那个主题的「订阅者」从「离线」变成在线。

**③ 手机**：`WOL-Setup-XXXX` 热点消失。

三条都对上，配置就彻底好了。

#### 第 9 步 · 发一条指令

巴法云控制台点「在线调试」，或直接在米家里点按，发 `on`。

串口（还在 30 秒窗口内）会打出：

```
I (16402) main: cmd "on"
I (16402) wol: broadcast address derived from netif: 192.168.1.255
I (16412) wol: magic packet sent to 192.168.1.255:9 for aa:bb:cc:dd:ee:ff
```

巴法云的调试面板还会收到设备主动回的两条消息：`ack:6f6e`（`on` 的十六进制，用来确认平台到底发了什么）和 `wol:sent`。

**电脑关机状态下，这条指令会让它开机。**

如果三条都齐了但电脑不启动，那不是板子的问题，去看第三节「电脑侧必做的三件事」——BIOS 里的 `ErP` 是头号嫌疑人。

### 结语

这个项目代码量不大，真正花时间的是那些看起来"应该很简单"的地方：为什么连不上 WiFi、为什么串口消失了、为什么电池掉得比算的快。

踩完了回头看，最有价值的其实不是 WOL 本身，而是那套**「让一台已经装进机箱、只靠电池活着的设备仍然可以被远程维护」**的思路。希望对做同类项目的朋友有点用。
